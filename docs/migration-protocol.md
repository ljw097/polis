# 이주 프로토콜

이주하는 도중에도 패킷을 하나도 잃지 않고, 틱도 밀리지 않게 하는 규칙이에요.
입법 모드 프로그램은 결정적이어야 해서, 이 프로토콜은 "대체로 잘 됨"이 아니라 **항상 정확**해야 해요.
코드: `sim/polis/protocol.py`, 실험: `experiments/e04_migration_protocol.py`.

## 문제

보내는 쪽은 받는 노드의 **주민번호(가상 ID)**만 알아요. 그 노드는 지난번 이후 이사했을 수 있어요.

## 구성 요소

| 요소 | 비유 | 역할 |
|---|---|---|
| **본적지 디렉터리** | 주민센터 | 모든 ID에는 본적지 타일 `home(id) = id mod 타일 수`가 있고, 본적지는 그 노드의 현재 주소를 항상 알아요. |
| **주소 캐시** | 내 주소록 | 각 타일은 자주 보내는 ID의 주소를 기억해요 (가상 메모리의 TLB). 모르면 본적지에 물어요 (메시지 2개). |
| **전송 포인터** | 우편물 전송 신청 | 노드가 떠난 타일은 `fwd_ttl` 틱 동안 새 주소를 남겨요. 옛 주소로 온 패킷은 전달되고, 보낸 쪽 주소록도 고쳐줘요 (메시지 1개). |
| **비상 경로** | 주민센터 문의 | 옛 주소에 포인터도 없으면, 그 타일이 본적지에 물어서 전달해요. |
| **틱 장벽** | 회기 | 이주는 틱과 틱 사이에만 일어나요. 한 틱은 그 틱의 패킷이 전달된 패킷까지 모두 도착해야 끝나요. |

**정확성의 근거**: 본적지는 늘 최신 주소를 알고, 어떤 패킷이든 결국 본적지를 거쳐 갈 수 있어요.
그래서 전송 포인터와 캐시는 **속도**를 위한 장치일 뿐이고, 정확성은 본적지와 틱 장벽이 보장해요.
전달 때문에 늦어진 패킷은 틱 장벽이 기다려주므로, 시간 지연은 생겨도 계산 결과는 달라지지 않아요.

## 이주 절차 (노드 u: 타일 A → B)

1. 틱 t의 계산과 전달이 모두 끝날 때까지 기다려요 (틱 장벽).
2. A가 u의 상태를 B로 보내요: 전위, 임계값, 부호, **바깥 연결 표 전체**, 공로.
   연결 표는 보내는 쪽에 저장되므로 노드와 함께 이사해요. 받는 쪽은 아무것도 고칠 필요가 없어요.
3. A는 전송 포인터 `u → B`를 남겨요.
4. u의 본적지에 새 주소 B를 알려요 (메시지 1개).
5. 틱 t+1 시작.

연쇄 이주(A→B→C)는 포인터가 사슬처럼 이어져서 그대로 따라가요.

## 실험 결과 (e04)

프로그램: 입법 모드 8비트 리플 캐리 덧셈기 (노드 89개, 연결 144개).
덧셈 200번, 각 40틱. 타일 16개. 입출력 포트는 고정. 무작위 노드가 무작위 타일로 이주.

| 틱당 이주 | 방식 | 정답 | 잃은 패킷 | 제어 메시지 / 패킷 |
|---|---|---|---|---|
| 0.05 | 순진 (캐시 갱신·전송 없음) | 4/200 | 73% | 0.003 |
| 0.05 | **Polis** | **200/200** | 0 | 0.005 |
| 0.5 | 순진 | 0/200 | 92% | 0.021 |
| 0.5 | **Polis** | **200/200** | 0 | 0.030 |
| 5 (극한) | 순진 | 0/200 | 93% | 0.201 |
| 5 (극한) | **Polis** | **200/200** | 0 | 0.188 |

(Polis 행은 `fwd_ttl=512`. 순진 방식은 잃은 패킷 때문에 활동이 줄어서 패킷 수 자체가 적어요.)

관찰:

1. **순진한 방식은 이주가 드물어도 무너져요.** 틀린 주소록은 누가 고쳐주지 않는 한 영원히 틀려서, 손상이 계속 쌓여요.
   주소록 교정은 선택 사항이 아니에요.
2. **Polis의 비용은 작아요.** 현실적인 빈도(틱당 0.05–0.5번)에서 패킷 100개당 제어 메시지 0.5–3개.
3. **전송 포인터 수명은 길수록 좋아요.** 수명이 짧으면 포인터가 사라진 뒤 본적지 문의(비상 경로)가 늘어요.

   | 틱당 이주 5번 | 전달 | 본적지 비상 문의 |
   |---|---|---|
   | `fwd_ttl=8` | 31,413 | 18,051 |
   | `fwd_ttl=512` | 96,773 | 128 |

   포인터는 노드 ID와 주소만 담은 작은 항목이라, 길게 유지하는 비용이 낮아요.

## 하드웨어 요구사항

- 타일마다: 주소 캐시, 전송 포인터 표, 자기가 본적지인 ID들의 디렉터리 조각.
- 디렉터리 전체 크기 = 노드 수 × 주소 비트. 타일에 고르게 나뉘어요.
- 틱 장벽은 구역 대표가 "우리 구역 이번 틱 끝"을 모아 의회로 올리는 방식으로 구현할 수 있어요.
  이주를 협상하는 연방 구조가 틱 동기화도 맡게 되는 셈이에요.

## 아직 시뮬레이션하지 않은 것

- 패킷의 실제 전송 지연과 틱 장벽의 시간 비용 (지금은 논리적 정확성과 메시지 수만 측정).
- 캐시 용량 제한과 교체 정책.
- e01의 연방 이주(구역 자치, 의회)와 이 프로토콜의 결합.
