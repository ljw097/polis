# 네트워크와 외부 호환

원칙: **안쪽은 자체 패킷, 바깥쪽은 표준.** Polis는 인터넷 위의 평범한 장비처럼 TCP/UDP로 대화해요.
코드: `sim/polis/gateway.py`, 데모: `experiments/e05_network.py`.

## 계층

| 범위 | 쓰는 것 | 이유 |
|---|---|---|
| 타일 사이 (칩 안) | 자체 스파이크 패킷 (주민번호 + 세기) | 패킷이 수십 비트면 충분. 표준 헤더를 붙이면 몇 배 낭비 |
| 칩렛 사이 | UCIe | 칩렛 연결의 표준. 구역 하나 = 칩렛 하나로 나누기 좋음 |
| 호스트 CPU와 | CXL (PCIe 기반) | Polis의 포트와 노드 표를 메모리처럼 노출 |
| 기기 사이, 외부 | **이더넷 + IP + UDP/TCP** | 기존 망, 스위치, 운영체제, 소켓 프로그램과 그대로 호환 |

## 관문 (gateway) 타일

가장자리 타일 일부는 표준 이더넷 포트와 작은 일반 코어(예: RISC-V)를 가져요.
이 코어가 기존 TCP/IP 스택을 그대로 돌리고, 소켓 메시지와 포트 이벤트를 서로 번역해요.

- **UDP**: 데이터그램 하나 = 메시지 하나. 거의 그대로 입력 포트 이벤트로 풀려요.
- **TCP**: 재전송, 순서 보장, 흐름 제어처럼 상태가 많은 일은 관문 코어가 맡아요.
  스파이크로 TCP 상태 기계를 흉내 내는 건 가능하지만(입법 모드로) 비효율적이라 하지 않아요.
- 관문은 입출력 포트와 같은 가장자리에 있고, 이주 대상에서 빠져요.

## 주소

- Polis 기기 하나에 IPv6 대역 하나(예: /64)를 줘요.
- 포트 ID(필요하면 가상 노드 ID)를 주소 아래쪽 비트에 대응시켜요.
  바깥에서는 노드 하나하나가 주소로 보이지만, 칩 안에서는 짧은 ID만 오가요.
  관문에서만 전체 헤더를 붙였다 떼요 (저전력 망의 6LoWPAN 헤더 압축과 같은 발상).
- v0 시뮬레이터는 IPv4 소켓 하나와 메시지 안의 포트 번호로 이를 대신해요.

## NEP v1 (Nomos Event Protocol)

UDP/TCP 위에 얹는 메시지 형식이에요. 빅엔디언. TCP에서는 메시지마다 앞에 4바이트 길이를 붙여요.

| 메시지 | 내용 |
|---|---|
| 공통 헤더 | `"NM"`, 버전(1), 종류 |
| RUN (1) | 틱 수, 이벤트 n개 × (입력 포트, 시작 틱, 끝 틱) — 그 구간 동안 입력을 켜둠 |
| RESULT (2) | 출력 포트 n개 × (포트, 발화 횟수, 마지막 발화 틱) |
| PORTS (3) | 포트 목록 조회: (번호, 입력/출력, 이름) |
| ERROR (4) | 오류 메시지 — 잘못된 요청에도 관문은 죽지 않고 이걸 돌려줘요 |

8비트 덧셈 요청은 38바이트예요.

## 데모 결과 (e05)

평범한 소켓 클라이언트가 입법 모드 8비트 덧셈기를 호출해요.

```
$ python experiments/e05_network.py 17 25
UDP: 17 + 25 = 42
TCP: 17 + 25 = 42
```

`tests/test_gateway.py`: 무작위 덧셈 30개를 UDP·TCP 각각으로 확인하고, 잘못된 요청에 오류를 돌려준 뒤에도 계속 동작하는지 확인해요.

## 남은 것

- **스트리밍**: 지금은 요청 하나에 실행 한 번. 센서처럼 계속 들어오는 입력은 UDP 이벤트 스트림으로 확장 (실행을 멈추지 않고 이벤트를 흘려 넣기).
- **보안**: 인증, 암호화(DTLS/TLS)는 관문 코어의 표준 스택으로 처리 예정.
- **기기 간 Polis 연결**: 구역 사이 패킷을 UDP로 감싸 이더넷으로 보내기. RDMA를 UDP 위에 얹은 RoCEv2와 같은 방식.
- 기존 명령어(x86, ARM 등) 에뮬레이션은 범위 밖. 서드파티 몫이에요.
