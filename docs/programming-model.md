# 프로그래밍 모델

Polis에 일을 시키는 방법이에요. 이 결정이 타일, 패킷, 이주 프로토콜의 요구사항을 정해요.

## 결론

**프로그램 = 연결 그래프.** 그래프를 만드는 방법은 세 가지이고, 셋 다 같은 하드웨어 위에서 돌아요.

| 모드 | 비유 | 어떻게 | 성질 |
|---|---|---|---|
| **입법 (compile)** | 법을 써서 공포 | 노드와 연결을 직접 써넣음 | 결정적, 재현 가능, 학습 없음 |
| **교육 (learn)** | 관습이 굳어짐 | 입력과 보상으로 연결이 자람 (헌법 2–8조) | 확률적, 적응형 |
| **혼합** | 법 + 관습 | 뼈대는 입법, 일부 연결만 학습 허용 | 정확한 부분과 적응하는 부분이 공존 |

Polis의 정체성은 **범용 컴퓨터이면서, 회로를 쓰는 중에도 바꿀 수 있는 컴퓨터**예요.
학습은 핵심 기능이지만 필수 조건은 아니에요.

## 근거: 입법 모드로 범용성 확인

`sim/polis/program.py`, `tests/test_program.py`. 학습 없이 연결만 써넣어서 만든 것들이에요.

- **게이트**: OR(가중치 1+1, 임계값 1), AND(0.5+0.5), XOR(OR를 억제성 AND가 한 틱 뒤에 거부).
- **반가산기**: 합 = XOR, 올림 = AND. 진리표 4경우 모두 통과.
- **1비트 메모리 (래치)**: 자기 자신에게 연결된 노드가 계속 발화하며 값을 기억하고, 억제 노드가 끄면 꺼져요.

게이트와 메모리가 있으면 원리상 어떤 디지털 회로든 조립할 수 있어요.
(e03에서 보상만으로는 못 배운 XOR을 입법 모드에서는 노드 3개로 바로 만들었어요.)

## 실행 의미론

- **시간**: 전역 틱. 한 틱 동안 모든 노드가 받은 신호를 처리하고, 다음 틱에 내보내요.
  물리적으로는 클럭 없는 이벤트 구동으로 구현할 수 있지만, 프로그래머가 보는 의미는 틱이에요.
- **입력 포트**: 가장자리 노드. 외부가 "몇 번째 틱에 발화"를 주입해요.
- **출력 포트**: 가장자리 노드. 결과는 "몇 번째 틱에 발화했나" 목록이에요.
- **값의 표현**: 비트 = 정해진 시간 창 안에서 발화했는지 여부. 숫자 = 여러 비트, 또는 발화 횟수(교육 모드).
- **종료**: 정해진 틱 수가 지나거나, 아무 노드도 발화하지 않는 정적 상태에 도달하면 끝나요.
- **결정성**: 입법 모드에서는 잡음과 학습을 끄므로 같은 입력에 늘 같은 출력이 나와요.
  교육 모드에서는 탐색을 위해 잡음이 필요해요 (e03의 발견).

## 하드웨어에 대한 요구사항

이 모델에서 아래층 설계에 필요한 것들이 나와요.

1. **노드 항목**: 임계값, 부호(흥분/억제), 현재 전위, 휴지 카운터, 발화율 기록(항상성용).
2. **연결 항목**: 목적지 ID, 가중치, 그리고 **학습 허용 비트** 하나.
   혼합 모드는 이 비트로 구현해요. 입법한 연결은 잠그고, 열린 연결만 2–8조를 따라요.
   - 공로(8조)를 쓰려면 학습 허용 연결마다 공로 누적값이 하나 더 필요해요.
3. **포트**: 입력·출력 노드는 가장자리 타일에 고정해서 이주 대상에서 빼요.
4. **로더**: 그래프를 처음 배치할 때는 그래프 분할로 무작위보다 나은 초기 배치를 정하고, 그 뒤는 이주가 다듬어요.
5. **이주 중 정확성**: 입법 모드는 결정적이어야 하므로, 이주 도중에도 패킷이 사라지거나
   틱이 밀리면 안 돼요. → 이주 프로토콜의 엄격한 요구사항이에요 (다음 설계 항목).

## 열린 질문

- **지연**: 연결마다 지연(틱 수)을 둘까요? 두면 타이밍 회로가 쉬워지지만 연결 항목이 커져요.
- **가중치 정밀도**: 입법 모드에 필요한 비트 수(지금 예제는 0.5, 1, 2, 5 정도면 충분).
- **틱 동기화**: 클럭 없는 물리 구현에서 "틱"의 의미를 어떻게 보장할까요. 이주 프로토콜과 같이 풀어야 해요.
