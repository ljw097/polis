# 칩 내부 패킷과 라우팅

코드: `experiments/e06_packets.py`.

## 결정: 타일 단위 패킷 (방식 B)

스파이크 하나는 **목적지 타일마다 패킷 하나**가 돼요. 받는 타일이 자기 표를 보고 안에서 나눠줘요.

```
| type 4 | dst tile 12 | src node 24 |   = 40 bit
```

- `dst tile`: 64×64 타일 격자 (4096 타일)까지. 라우터는 이것만 봐요.
- `src node`: 가상 노드 1600만 개까지. 받는 타일이 `src → [(내 노드, 가중치), ...]` 표를 찾아요.
- 가중치는 받는 쪽 표에 있어서 패킷에 없어요.
- 제어 메시지(이주, 디렉터리, 틱 장벽)는 `type`으로 구분하고 같은 망을 써요.

비교한 대안 A (연결마다 패킷, 보내는 쪽이 가중치 보유):

```
| type 4 | dst tile 12 | dst node 24 | weight 8 |   = 48 bit
```

## 라우팅

- 타일 격자 위 XY 차원 순서 라우팅 (X 먼저, 그다음 Y). 교착이 없고 구현이 단순해요.
- 링크 하나는 사이클당 48비트 플릿 하나를 옮긴다고 가정.
- **틱 길이 추정** = max(가장 붐비는 링크의 부하, 가장 긴 경로). 혼잡한 메시의 하한이에요.
  라우터 파이프라인 깊이, 타일 안 주입·배출 대역폭은 아직 모델링하지 않았어요.

## 결과 (e06)

e01과 같은 필드 (노드 1024개, 8×8 타일), 마지막 600틱 평균. 범위는 시드 0–1.

| 배치 | 방식 | 틱당 패킷 | 틱당 kbit·hop | 틱 길이 (사이클) |
|---|---|---|---|---|
| 고정 | A | 51–128 | 12.9–35.4 | 12–24 |
| 고정 | B | 50–120 | 10.7–27.5 | 11–21 |
| 연방 이주 | A | 51–128 | 2.4–6.5 | 10–28 |
| 연방 이주 | **B** | **24–58** | **1.1–3.2** | **6–12** |

1. **이주만으로는 틱이 짧아지지 않아요.** 전송량은 1/5로 줄지만, 노드가 모이면서 그 주변 링크가 막혀요.
   시드 1에서는 틱이 오히려 길어졌어요 (24 → 28).
2. **B만으로도 부족해요.** 목적지가 흩어져 있으면 같은 타일로 가는 패킷이 거의 없어서 묶을 게 없어요.
3. **둘을 합치면** 이주가 목적지를 같은 타일로 모아주고, B가 그걸 패킷 하나로 묶어요.
   패킷 절반, 전송량 1/10, 틱 길이 절반.

## 다른 설계에 미치는 영향

- **연결 표가 받는 쪽으로 이동.** 노드가 이주할 때 자기에게 **들어오는** 연결 표(src → 나, 가중치)를 들고 가요.
- **보내는 쪽은 "목적지 타일 목록"만 보유.** 주소 캐시가 `dst 노드 → 타일` 대신 `나 → 보낼 타일 목록`이 돼요.
  이주 후 교정 메시지는 이 목록을 고쳐요. [이주 프로토콜](migration-protocol.md)의 정확성 논리(본적지 + 전송 포인터 + 틱 장벽)는 그대로예요.
- **학습(4조 새 연결)**: 새 연결은 받는 타일 표에 항목 추가 + 보내는 쪽 목록에 타일 추가.

## 남은 것

- 주입·배출 대역폭과 라우터 파이프라인을 넣은 사이클 단위 모델.
- 같은 타일 안 패킷(홉 0)의 처리 비용.
- 큰 규모(4096 타일)에서의 확장성.
