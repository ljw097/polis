# RTL v0

`rtl/`: Verilog-2005, 합성 가능. 입법 모드(누설 0, 휴지 0, 학습 없음)를 구현해요.

| 파일 | 내용 |
|---|---|
| `polis_tile.v` | 타일: 설정 쓰기 포트, 송신(팬아웃), 수신(해시 색인 + 선형 탐색, 인라인/세그먼트 시냅스), 누산, 갱신 |
| `polis_router.v` | 5포트 라우터: XY 라우팅, 입력당 2칸 FIFO, 출력별 라운드로빈 중재, 40비트 단일 플릿 |
| `polis_mesh.v` | 최상위: G×G 타일 + 라우터, 틱 장벽(보낸 패킷 수 = 처리한 패킷 수 + 모든 타일 송신 완료) |

## 검증: 파이썬 모델과 공동 시뮬레이션

`tools/rtl_build.py`가 하는 일:
1. 프로그램을 `hw.Chip`(파이썬 하드웨어 모델)에 올려요.
2. 그 표를 RTL 메모리 형식(해시 표, 인라인 항목, 세그먼트)으로 변환하고 테스트벤치를 생성해요.
3. Verilator(또는 iverilog)로 RTL을 돌려서 **매 틱 발화한 노드 집합**을 파이썬 모델과 비교해요.

| 시나리오 | 메시 | 노드 | 틱 | 스파이크 | 불일치 틱 | 색인 실패 |
|---|---|---|---|---|---|---|
| 8비트 덧셈기, 덧셈 8번 | 4×4 | 89 | 320 | 11,752 | 0 | 0 |
| 무작위 프로그램, 시드 0–2 | 4×4 | 512 | 40 × 3 | 25,936 | 0 | 0 |
| 무작위 프로그램, 시드 0–2 | 8×8 | 1024 | 40 × 3 | 51,186 | 0 | 0 |

무작위 프로그램: 임계값 0.5–2.5, 가중치 ±1/16–2, 억제 노드 25%, 노드당 연결 6개, 매 틱 외부 입력 4%.
해시 충돌, 긴 세그먼트, 음의 가중치, 네트워크 혼잡을 모두 거쳐요.

```
python tools/rtl_build.py adder
python tools/rtl_build.py fuzz 3
pytest tests/test_rtl.py        # Verilator가 있으면 실행
```

## 합성 (Yosys 0.33, 일반 CMOS 게이트)

설정: 타일당 노드 256, 색인 4096칸, 시냅스 저장소 4096칸, 팬아웃 표 4096칸. 스크립트: `rtl/synth/*.ys`.

| 블록 | 게이트 트랜지스터 | 플립플롭 | 합계 (플립플롭 24T 가정) |
|---|---|---|---|
| 타일 | 40,390 | 472 | 약 51,700 |
| 라우터 | 35,572 | 425 | 약 45,800 |
| **타일 + 라우터** | | | **약 97,500** |

메모리 9개(임계값, ID, 팬아웃 포인터, 팬아웃, 색인, 시냅스, 누산기, 건드린 목록, 발화 목록)는 SRAM으로 따로 계산해요.
타일당 377,856비트 = **46.1 KiB**.

### 타일 하나의 면적 추정

| 항목 | 가정 | 면적 |
|---|---|---|
| 로직 | 65–134 MTr/mm² (N5급: 고성능 라이브러리 ~ Apple A14 실측 평균) | 0.0007–0.0015 mm² |
| SRAM 46.1 KiB | 25–38.1 Mb/mm² 매크로 | 0.010–0.015 mm² |

**로직은 SRAM의 약 1/10이에요.** 칩 면적은 거의 메모리가 정해요.
그래서 [scale.md](scale.md)에서 본 메모리 밀도 문제가 곧 면적 문제예요.

e08의 로직 가정(타일당 0.01–0.05 mm²)은 너무 컸어요. 아래 이유로 실제는 지금 합성 결과보다 크겠지만,
타일당 0.002–0.01 mm² 정도로 고쳐 잡는 게 맞아요. 그러면 노드 26만 개 칩은 약 **19–35 mm²**예요 (SRAM 17–25 + 로직 2–10).

## 아직 없는 것 (합성 결과가 작게 나오는 이유)

- **학습부** (2–8조), 누설·휴지 타이머
- **제어부**: 주소 캐시, 전송 포인터, 디렉터리 조각, 이주 DMA. 지금 RTL은 노드가 이사하지 않아요
- **관문 타일** (이더넷, TCP/IP 코어)
- **SRAM 타이밍**: 지금은 메모리를 비동기 읽기 배열로 써요. 실제 SRAM은 동기식이라 수신·갱신 경로를 파이프라인으로 나눠야 해요
- **갱신 병렬화**: RTL은 사이클당 노드 1개 (모델은 8개 가정)
- **타이밍 분석**: 공정 라이브러리가 없어서 클록 주파수는 아직 몰라요
- 배선, 클록 트리, 테스트 회로 등 실제 칩 오버헤드
